# Control Center slice 7b: font weights and sizes from the design system, and a tidier top of the Audio page

**Tier: S, because** it adds seven token values, applies them in CSS and moves markup between two Svelte files; nothing is read, written or spawned differently, and it reverts with `git revert`. It edits `app/packages/design-system` (tokens and golden only), so the `app/` preview gate in Done applies.

**User story:** As the person running this project, I want Control Center's text to match the web app: a bold page title, semibold header title, step titles, buttons and nav items, normal weight everywhere else, at sensible sizes (page title big, subtitle clearly smaller but bigger than body text, step titles smaller than today). The run picker and delete button sit on the same row as the player controls, the picker as tall as the buttons and Delete a trash icon button at the far right, with more space under the subtitle. The values come from the design system.

Written against: `6388f99` (docs commits since then touch only the plan folder) (branch `feat/control-center-slice-7-theme`, local; commit on the same branch)  ·  Blocked by: slice 7 and its fix (built)  ·  Blocks: nothing.

Decisions (owner, 2026-09-30): page title 30px bold (the web app's `text-3xl font-bold`); subtitle 18px; step titles 18px semibold; gap under the subtitle tripled (today about 8px, so 24px = `--space-6`); picker and delete in the player row, Delete a lucide `trash` icon button at the right end.

Why component tokens, not typography: the generator writes `semantic.typography` leaves only into the generated CSS's `@theme inline` block, which Control Center does not use (`build-tokens.mjs:216-218`; proven by the slice 7 fix's executor). `component.*` leaves are emitted as real `:root` properties (Control Center already uses `--component-button-font-family`), so weights go there and no generator change is needed.

What the web app does today (the targets): header title `text-xl font-semibold` (`AppHeader.tsx:40`), buttons `font-semibold` (`Button.tsx:37`), tabs `font-semibold` (`SegmentedControl.tsx:83`), list titles `font-semibold` (`SongListRow.tsx:47`), page title `text-3xl font-bold` (`SongDetailPane.tsx:62,68`). Control Center sets no weights: its `h1`/`h2` get the browser's bold and its buttons normal.

## Changes (exact)

1. **Tokens (default brand, both files, same values, no `dark` entries).** The design-system editor builds its field list from `SECTIONS` in `field-descriptors.mjs` and throws `Unknown token section` for any `component.<group>` not listed there (only `colorField`, `slider`, `segmentedControl`, `button`, `iconButton` are), which would break the `/design-system` page and its e2e specs. So do **not** invent several groups. Add: (a) `component.button.fontWeight` = `600` (existing group); (b) one new group `component.text` with `pageTitleFontWeight` = `700`, `pageTitleFontSize` = `30px`, `pageSubtitleFontSize` = `18px`, `sectionTitleFontWeight` = `600` (step titles), `sectionTitleFontSize` = `18px`, `appHeaderTitleFontWeight` = `600`. Seven tokens in all. Weights use `$type: "number"` (the validator's `KNOWN_TYPES` in `tokens-validation.test.mjs` has no `fontWeight`; do not add one); sizes use `"dimension"`. Each has a `$description` in the file's style. Register the group with one new line in `SECTIONS`, after the `component.iconButton` entry and **without** a `group` property (sections without one render as plain flat sections, so `field-row.tsx` and the editor's preview union stay untouched): `{ key: "component.text", heading: "Text styles" },`. Expected generated names: `--component-button-font-weight`, `--component-text-page-title-font-weight`, `--component-text-page-title-font-size`, `--component-text-page-subtitle-font-size`, `--component-text-section-title-font-weight`, `--component-text-section-title-font-size`, `--component-text-app-header-title-font-weight`; regenerate (`npm run tokens` in `tools/Control_Centre/`) and use the names actually emitted in `:root`. Run the design-system tests and, from `app/`, `npm run verify`; if the editor or e2e needs more than the one registration line, STOP and report.
2. **Golden.** `build-tokens.test.mjs` pins the generated CSS (default brand and the `demo-child` inheritance test): add exactly the new lines; no other line may change. Diff the real generator output against the old golden and confirm only those seven lines (per test) are new.
3. **Apply.** Only via the variables: `AppHeader` title → the app-header-title weight; the page `h1` (`.page-title`) → page-title weight; `StepRow` `.title` (an `h2`) → section-title weight; every button style (`.btn` in `routes/audio/+page.svelte`, `Button.svelte`, the buttons in `TabPlayer.svelte`, the `.btn` in `ThemeToggle.svelte`, and the "Log ▸" toggle `.log-toggle` in `StepRow.svelte`, which is a button) → button weight. Nav items need nothing: `NavItem.svelte` renders `Button`, which gets the button weight. Sizes (pattern only; the names are the `component.text` ones above): `.page-title` → page-title size; `.subtitle` → subtitle size (normal weight); `StepRow` `.title` → section-title size. Everything else stays at the inherited normal weight; if a heading or `strong` you did not list still renders bold by browser default, leave it and list it in the report.
4. **Top of the page (markup), `routes/audio/+page.svelte`.** Replace the `.subtitle-row` block (both the run and the "No runs yet" branches) with: the `<p class="subtitle">` on its own (heading plus info icon as today; "No runs yet" in the empty branch); keep `formError` and `runNotFound` directly after the subtitle as they are today; then, **when `data.run` exists**, `{#key playerKey}<TabPlayer … />{/key}` exactly as today (the `{#key}` and its `playerKey` stay; dropping it breaks the player rebuild on run switch) with a new `trailing` snippet prop (next change) holding the run picker; **when there is no run**, a plain `<div class="empty-row">` right-aligned (`display: flex; justify-content: flex-end; gap: var(--space-2)`) with the same disabled `trash` icon button (same markup and `title`/`aria-label` as below) and the disabled picker.
5. **`TabPlayer.svelte`:** add optional `trailing?: Snippet` to `Props`, rendered at the right end of the existing `.controls` row: `{#if trailing}<div class="trailing">{@render trailing()}</div>{/if}` with `.trailing { margin-left: auto; display: flex; align-items: stretch; gap: var(--space-2); }` and `.controls { align-items: stretch; }` (keep the existing rules). No other change to the player.
6. **The trailing content (in `+page.svelte`, passed as `{#snippet trailing()}` to `TabPlayer`):** left to right: the run picker form (the existing `<form method="GET" action="/audio">` with its `<select>`), then the Delete form (existing `?/deleteRun` form and `use:enhance` confirm logic unchanged, same `disabled={data.busy || data.chainActive}`) whose button becomes `class="btn secondary icon"` holding `<Trash size={16} aria-hidden="true" />` (`import Trash from '@lucide/svelte/icons/trash'`), `title` and `aria-label` both `Move this run to the Trash`.
