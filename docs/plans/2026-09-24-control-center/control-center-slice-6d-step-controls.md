# Control Center slice 6d: one control bar above the steps, Full continue, reasons on the disabled Start, run details under an info icon

**Tier: Full, because** Full continue is another action that starts processes (it reuses the 6c chain); the rest is markup in one Svelte file. It reverts with `git revert`.

**User story:** As the person running this project, I want every step row to look and work the same (Log, Show in Finder, Start or Stop). Everything that drives the whole pipeline sits in one bar above the Ingestion row, on the right: Browse, the picked file with its (x), **Full start**, and a new **Full continue** that resumes the selected run from the first step that is not Done (or is Out of date) through Tab. A disabled Start, Full start or Full continue tells me why when I hover it, so the triangle warnings are gone. The subtitle stays "title — artist"; the duration, sample rate and channels move under an info icon.

Written against: `eda147e` (branch `feat/control-center-slice-6b-step-rows`, local; commit on the same branch)  ·  Blocked by: 6c (done, human-checked)  ·  Blocks: nothing.

Decisions (owner, 2026-09-30): one bar above step 1, both Full buttons in it; Full continue starts from the first step that is not Done or is Out of date (step 1 is never re-run by it); disabled reasons on steps 1 to 4 and on both Full buttons; subtitle order unchanged; run details in a hover/focus tooltip on an info icon.

## Changes (exact)

1. **`chain.ts` (TDD: each function's test first, see it fail, then implement).**
   - `firstPendingStage(manifest, runId, dirs, records): StageDef | null`: over `manifest.stages` with `argsFrom === "runDir"`, in order, the first whose `runStepStatus(...)` has `status !== "done"` or `outOfDate === true`; `null` when none.
   - `startChainFrom(manifest, stageId, runId, dirs): { busy: true } | { busy: false; execId: string }`: `startRunStage(manifest, stageId, runId, dirs)`; on `busy` return it; otherwise write `chain.json` `{ currentStage: stageId, execId, runId }` (through the module's existing private `writeChain`) and return `{ busy: false, execId }`. `advanceChain` needs no change: the steps after the first one run because the chain moves on after each `done`.
   - Tests in the file's existing style: `firstPendingStage` returns the first not-started step; skips Done steps; returns an Out of date Done step; returns `null` when all are Done and current; `startChainFrom` writes the chain and starts that stage; with a stage already live it returns `busy` and writes nothing; `startChainFrom` then `advanceChain` with a fabricated `done` record starts the following stage (the chain continues from the middle). Suite: 139 plus these, `fail 0`.
2. **`fullContinue` action** in `+page.server.ts`, modelled on `startStage` and `fullStart`: read `runId` (and optional `confirmed === "1"`) from the form; `resolveRunDir(RUNS_DIR, runId) === null` → `fail(400, { error: "badRun" })`; `anyStageLive` or `readChain(DATA_DIR) !== null` → `fail(409, { busy: true })`; `stage = firstPendingStage(...)`, `null` → `fail(409, { error: "nothingToContinue" })`; `canStart(...)` not ok → `fail(409, { error: "notAllowed", reason })`; `overwriteGate(..., confirmed)` not ok → `fail(409, { error: "needsConfirmation", reason })`; `startChainFrom(...)`, `busy` → `fail(409, { busy: true })`; then `ensureChainTicker(manifest, dirs)` and `return { started: true, execId }`. The client never names the stage. Later steps of the chain are not overwrite-gated (they are downstream of a re-run, so stale by definition); this is deliberate.
   - `actionErrorText` in `+page.svelte` gets `if (f.error === 'nothingToContinue') return 'Every step is already Done.';`.
3. **Control bar** in `+page.svelte`, between the tab player and step 1: `<div class="control-bar">` right-aligned (`display: flex; justify-content: flex-end; align-items: center; gap: var(--space-2); padding: var(--space-4) 0 0`), holding, in this order: the picked-file name span with its `title`, the clear (x) form, the Browse form (all moved unchanged from step 1's `before` snippet, same conditions), the Full start form (moved from step 1's `after`, unchanged), and a new Full continue form `method="POST" action="?/fullContinue"` with hidden `runId` (`data.run?.id ?? ''`), button `class="btn secondary"` text `Full continue`. Its `use:enhance` runs `confirm(overwriteConfirmText(continueStep))` and sets `formData.set('confirmed', '1')` when `continueStep.noRecord` (same as a step's Start), cancelling when declined. Step 1 then has no `before` snippet; its `after` holds Show in Finder and Start like every other step. Toast, `followIngest` and all fix-2/fix-3/6c behaviour stay as they are.
   - `continueStep = $derived(later.find((s) => s.status !== 'done' || s.outOfDate))` (the page-side twin of `firstPendingStage`; the server decides for real). Full continue is disabled when `!data.run || !continueStep || !continueStep.canStart || data.busy || data.chainActive`.
4. **Reasons on disabled buttons.** Replace the `.warn` triangle spans (and the `TriangleAlert` import, the `before` snippet of steps 2 to 4, the `.warn` CSS) with one wrapper: `<span class="tip" data-tip={reason}>…the button…</span>` around each of these buttons, where `data-tip` is empty (and the tooltip does not show) when the button is enabled or has no reason. `.tip:hover::after, .tip:focus-within::after` show the same tooltip box the old `.warn` used (same CSS, `bottom: calc(100% + 6px); right: 0`, shown only when `data-tip` is non-empty, e.g. `.tip[data-tip]:not([data-tip=""])`). `.tip button:disabled { pointer-events: none; }` so the wrapper receives the hover. Reasons:
   - Steps 2 to 4 Start: the step's existing `reason` when `!step.canStart && step.reason && step.status !== 'running'` (exactly the old triangle condition).
   - Step 1 Start: `data.chainActive` → `A Full start is running`; else `!data.picked` → `Browse a file first`; else empty. (Keep its `title="Ingest the picked file as a new run"` for the enabled case.)
   - Full start: `data.chainActive` → `A Full start is running`; `!data.picked` → `Browse a file first`; else `step1.status === 'running'` → `Ingestion is running`; else empty (its enabled title stays).
   - Full continue: `!data.run` → `No runs yet`; `data.chainActive` → `A Full start is running`; `data.busy` → `A step is running`; `!continueStep` → `Every step is already Done`; `!continueStep.canStart` → `continueStep.reason || 'Not ready yet'`; else enabled title `Continue from ${continueStep.label}`.
5. **Info icon.** Import `Info from '@lucide/svelte/icons/info'`. In the subtitle, keep `{heading}` exactly as today and remove the `· {duration}s · {rate} Hz · {ch}ch` text. After the heading, when `data.run.sampleRate > 0`, add `<span class="tip info" tabindex="0" role="img" aria-label={details} data-tip={details}><Info size={16} aria-hidden="true" /></span>` with `details = "{Math.round(durationSec)}s · {sampleRate} Hz · {channels}ch"` (same numbers and separators as today). Its tooltip opens below-left (`.info` overrides: `top: calc(100% + 6px); bottom: auto; left: 0; right: auto`). Needs the same `svelte-ignore a11y_no_noninteractive_tabindex` comment the old `.warn` span had.
6. **`STATUS.md`:** one sentence: one control bar above the steps (Browse, picked file, Full start, Full continue); disabled buttons explain why on hover; run details under an info icon.
