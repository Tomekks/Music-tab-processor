# Control Center slice 7: Geist fonts, dark mode button, status colours from the design system

**Tier: S, because** nothing reads, writes or spawns differently and it reverts with `git revert`; it does touch `app/packages/design-system` (new tokens only, so `docs/WEB_APP_WORKFLOW.md` applies to that part and the preview gate below is part of Done).

**User story:** As the person running this project, I want Control Center to look like the web app: the same Geist fonts, the same colours, and the same Sun/Moon button to switch between light and dark. Every value comes from the design system; where the design system had no value (the Done/Failed/Interrupted status colours), it gets one, with a dark variant.

Written against: master `b565b77` (PR #52 merged); branch `feat/control-center-slice-7-theme`, already cut from it with this spec as its first commit (commit the work on this branch).  ·  Blocked by: nothing  ·  Blocks: nothing.

Decisions (owner, 2026-09-30): fonts from the `@fontsource-variable` npm packages, served locally (no runtime request to Google); new semantic status tokens in the **default** brand with dark variants (other brands inherit); audit **every** hardcoded colour, font and font size in Control Center; the toggle sits in Control Center's header, right side, same Sun/Moon icon button as the web app.

Facts read from the code (verify, do not trust): Control Center already copies the generated tokens (`package.json` `tokens` script → `src/lib/design-tokens.generated.css`), which has `:root`, `[data-theme="light"]` and `[data-theme="dark"]` blocks, but nothing sets `data-theme`. The tokens `semantic.typography.sans`/`mono` are `var(--font-geist-sans)` / `var(--font-geist-mono)` (`brands/default/tokens.json:52-53`); only the web app's Next.js font loader defines those variables, so Control Center falls back to the browser default. The only hardcoded colours in `src` are the three in `src/lib/status-colors.css`; hardcoded fonts: `TabPreview.svelte:136-141` (`monospace`, `10px`) and `routes/audio/+page.svelte:451` (`0.85em`). The web app toggles with `useThemeMode` (`app/hooks/useThemeMode.ts`: `localStorage` key `guitar-tabs-theme`, else the system preference; writes `document.documentElement.dataset.theme`) and `ThemeToggle.tsx` (Sun while dark, Moon while light; label `Switch to <other> mode`).

## Changes (exact)

1. **Fonts.** In `tools/Control_Centre/` run `npm install @fontsource-variable/geist @fontsource-variable/geist-mono` (from the npm registry; both exist, 5.3.0). In `src/routes/+layout.svelte` add `import '@fontsource-variable/geist';` and `import '@fontsource-variable/geist-mono';`. In `src/lib/design-tokens.css`, after the import, add `:root { --font-geist-sans: 'Geist Variable', Arial, Helvetica, sans-serif; --font-geist-mono: 'Geist Mono Variable', ui-monospace, monospace; }` so the design system's own font tokens resolve. Confirm the family names against the installed packages' CSS (`node_modules/@fontsource-variable/geist/index.css`); use what is there. Do **not** change the design system's font tokens (the web app keeps defining these variables itself). Set the page body to the sans token: `body { font-family: var(--font-sans); }` if no rule already does.
2. **Status tokens in the design system (TDD: the design system's own tests must stay green).** In `brands/default/tokens.json` add to `semantic.color`: `statusDone`, `statusFailed`, `statusError`, each with a `$type: "color"` and a `$description` in the file's existing style; light values keep today's colours (`#2e7d32`, `#c62828`, `#e67e00`); add dark variants under `dark.semantic.color` with values that pass `contrast.test.mjs`'s rules against the dark background `#1c1d1f` (start from lighter tints such as `#66bb6a`, `#ef5350`, `#ffa726`; adjust only if the contrast test rejects them). `primitive.*` stays alias-only per the package convention. The orphan test (`token-usage.test.mjs`) requires every new leaf to be referenced somewhere it scans: add `join(APP_ROOT, "../tools/Control_Centre/src")` to `SCAN_ROOTS` and `".svelte"` to `SCAN_EXTENSIONS` so the references in change 3 count. No other edit to that test.
3. **Use the status tokens.** Regenerate (`npm run tokens`) and replace every `var(--status-done)`, `--status-failed`, `--status-error` in Control Center with the generated names for the new tokens (look them up in `design-tokens.generated.css`, expected `--color-status-done`, `--color-status-failed`, `--color-status-error`). Delete `src/lib/status-colors.css` and its import in `+layout.svelte`. The Done/Failed/Interrupted dots must look the same as before in light mode.
4. **Dark mode button (TDD for the pure logic).**
   - `src/lib/theme.ts` (test first, see it fail): `export type ThemeMode = 'light' | 'dark'`; `export const THEME_STORAGE_KEY = 'guitar-tabs-theme'`; `export function resolveTheme(stored: string | null, systemDark: boolean): ThemeMode` (a stored `light` or `dark` wins, anything else follows `systemDark`); `export function nextTheme(mode: ThemeMode): ThemeMode`. Tests: stored light/dark win over the system; null and junk values follow the system; `nextTheme` both ways.
   - `src/app.html`: an inline `<script>` in `<head>`, before `%sveltekit.head%`, that sets `document.documentElement.dataset.theme` using the same rule (stored `light`/`dark`, else `matchMedia('(prefers-color-scheme: dark)')`), inside `try/catch` (falls back to light), so there is no flash of the wrong theme. Keep it a few lines; it duplicates `resolveTheme` on purpose (it runs before any module loads) and carries a one-line comment saying so.
   - `ThemeToggle.svelte`: one icon button like the web app's (`@lucide/svelte/icons/sun` while dark, `@lucide/svelte/icons/moon` while light, `aria-label="Switch to light mode"` / `"Switch to dark mode"`, `title` the same). On mount it reads `document.documentElement.dataset.theme`; on click it computes `nextTheme`, sets `dataset.theme`, and writes `localStorage[THEME_STORAGE_KEY]` inside `try/catch`. Styled with the same tokens as the `.btn.secondary.icon` buttons on the audio page (copy that look; do not import from the page).
   - `AppHeader.svelte`: render `<ThemeToggle />` at the right end (`margin-left: auto`).
   - `src/lib/design-tokens.css`: add `[data-theme='dark'] { color-scheme: dark; } [data-theme='light'] { color-scheme: light; }` so native controls (the run picker, scrollbars) follow the theme.
5. **Audit (every hardcoded colour, font, font size).** Search all of `tools/Control_Centre/src` (`.svelte`, `.css`, `.ts`, `.html`; not generated files, not tests) for hex, `rgb(`, `hsl(`, named colours used as values (`white`, `black`, …), `font-family`, `font-size`, `font-weight` and raw `px`/`em` font sizes. Report the full list in the execution report. Replace each with an existing token (`--foreground`, `--background`, `--color-border`, `--color-surface`, `--color-surface-text`, `--color-accent`, `--font-sans`, `--font-mono`, `--space-*`, …). Known ones to start with: `TabPreview.svelte:136-141` (`font-family: monospace` → `var(--font-mono)`; keep its numeric font size if it is a layout constant of the strip and say so in the report), `routes/audio/+page.svelte:451` (`0.85em` tooltip size: keep if the design system has no type-scale token, and list it as a gap). **If no token fits a colour or font**, add one to the default brand's `tokens.json` (semantic layer, with a `$description` and a dark variant for colours) under the same orphan-test rule, and list it in the report. SVG attributes that use `currentColor` or CSS variables are fine.
6. **`STATUS.md`:** one sentence: Geist fonts, the light/dark button and the status colours come from the design system.
