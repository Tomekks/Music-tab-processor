# Metronome IconButton Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the metronome/transport controls' hand-rolled buttons with a new `IconButton` design-system primitive (icon-only, 3 variants, 44×44px, `lucide-react` icons), extend BPM range/step controls, and migrate the mobile drawer-open button to the same primitive.

**Architecture:** A new `IconButton` primitive is added to `app/packages/design-system/src/components/`, backed by a new `component.iconButton.*` token block (mirroring the existing `component.button.*` pattern in `Button.tsx`). Every existing transport control (`ResetButton`, `PlayButton`, `MidiButton`→`VolumeButton`, `StringOrientationToggle`) is migrated onto it one behavioral group at a time, each migration keeping its existing external prop contract so `DetailToolbar.tsx` needs only minimal changes. BPM gains `-`/`+` `IconButton`s and a wider range. `HeaderSongsButton` (mobile drawer toggle) is migrated last, as it touches an unrelated part of the app.

**Tech Stack:** Next.js 16 / React 19 / TypeScript, Tailwind v4 (CSS custom properties via arbitrary-value classes), `lucide-react` (new dependency), Playwright (`@playwright/test`) for e2e, Node's built-in `node --test` for the design-system unit tests. No component-level test renderer exists in this repo (no jsdom/testing-library) — new UI is verified via Playwright against the real running app, matching this repo's existing convention.

**Spec:** This plan implements the design agreed in the grilling-skill interview session dated 2026-09-25 (no separate spec file was written; the consolidated spec is the interview's final summary, restated in full in the Global Constraints below and per-task detail).

## Global Constraints

- **Icon source:** `lucide-react` only, no other icon library, no hand-drawn SVGs.
- **Icon stroke width** is a single global per-brand design token (`component.iconButton.strokeWidth`), not a per-instance prop.
- **`IconButton` variants:** exactly `"primary"` (accent fill, permanent — not a toggle state), `"secondary"` (gray fill), `"ghost"` (transparent). Shape is rounded-square (reuses `semantic.radius.base`), never `rounded-full`.
- **Touch target:** every `IconButton` is 44×44px minimum (`component.iconButton.size`), matching the existing `min-h-[44px]` convention this app already enforces everywhere.
- **BPM range:** 20–500 (raised from 20–300). Step buttons move by 5. Typing in the input still allows any integer in range. At either boundary the `+`/`-` button stays clickable and silently clamps (no `disabled`, no error).
- **Umami:** `play`/`pause`/`reset`/`flip-strings`/`clear-loop` event names are unchanged. `toggle-midi-sound` is renamed to `toggle-volume` (analytics continuity break accepted). New events: `bpm-increment`, `bpm-decrement` (each carrying the resulting bpm value as `data-umami-event-bpm`), `open-songs-drawer` (new, previously untracked).
- **No functional behavior changes** beyond what's explicitly listed above — Flip-strings' actual orientation-flip logic, Reset's actual reset logic, Loop's pill/clear behavior when a range is set, and BPM's draft/commit/clamp mechanics all keep their current behavior; only presentation changes unless a task says otherwise.
- **`CONTEXT.md` and `CONTEXT-MAP.md` are out of scope** for this plan (explicitly deferred during the design interview — not enough content yet to justify a multi-context split).
- Every file edit must keep `npm run typecheck` (`app/`) passing; every task's own test command must pass before committing.

- [ ] **Step 2: Write `IconButton.tsx`**

Create `app/packages/design-system/src/components/IconButton.tsx`:

```tsx
"use client";

import { forwardRef } from "react";
import type { ButtonHTMLAttributes } from "react";
import type { LucideIcon } from "lucide-react";
import { stateOverlayClassName } from "./state-overlay.mjs";

// Icon-only counterpart to Button.tsx: same token-driven variant approach
// (component.iconButton.* mirrors component.button.*), but square/44px and a
// third "ghost" (transparent) variant since the mobile drawer toggle (a later
// task) needs no fill at all, unlike anything Button.tsx's two variants cover.
export interface IconButtonProps extends Omit<ButtonHTMLAttributes<HTMLButtonElement>, "children"> {
  icon: LucideIcon;
  variant?: "primary" | "secondary" | "ghost";
  "aria-label": string;
  // data-* attributes (e.g. data-umami-event, data-umami-event-enabled) are
  // not covered by ButtonHTMLAttributes' declared props on a custom
  // component (unlike a raw <button>, which TypeScript special-cases) --
  // this index signature lets every existing data-umami-event-* call site
  // keep working unchanged.
  [dataAttr: `data-${string}`]: string | boolean | undefined;
}

const FOCUS_RING =
  "focus-visible:[outline:var(--focus-ring-width)_solid_var(--focus-ring-color)] focus-visible:[outline-offset:var(--focus-ring-offset)]";
const DISABLED = "disabled:opacity-[var(--state-disabled-opacity)] disabled:cursor-not-allowed";
const PRIMARY_HOVER = stateOverlayClassName(
  "hover",
  "--state-hover-opacity",
  "--component-icon-button-primary-background",
  "--component-icon-button-primary-icon",
);
const PRIMARY_PRESSED = stateOverlayClassName(
  "active",
  "--state-pressed-opacity",
  "--component-icon-button-primary-background",
  "--component-icon-button-primary-icon",
);

export const IconButton = forwardRef<HTMLButtonElement, IconButtonProps>(function IconButton(
  { icon: Icon, variant = "secondary", disabled, className, ...rest },
  ref,
) {
  const variantClasses =
    variant === "primary"
      ? `border-transparent bg-[var(--component-icon-button-primary-background)] text-[var(--component-icon-button-primary-icon)] ${PRIMARY_HOVER} ${PRIMARY_PRESSED} disabled:hover:bg-[var(--component-icon-button-primary-background)] disabled:active:bg-[var(--component-icon-button-primary-background)]`
      : variant === "secondary"
        ? "border-[var(--component-icon-button-secondary-border)] bg-[var(--component-icon-button-secondary-background)] text-[var(--component-icon-button-secondary-icon)] hover:bg-surface-hover"
        : "border-transparent bg-transparent text-[var(--component-icon-button-ghost-icon)] hover:bg-surface-hover";

  return (
    <button
      type="button"
      ref={ref}
      disabled={disabled}
      className={[
        "inline-flex cursor-pointer items-center justify-center border shrink-0 transition-colors",
        "h-[var(--component-icon-button-size)] w-[var(--component-icon-button-size)]",
        "rounded-[var(--component-icon-button-radius)]",
        FOCUS_RING,
        DISABLED,
        variantClasses,
        className,
      ]
        .filter(Boolean)
        .join(" ")}
      {...rest}
    >
      {/* Icon-level strokeWidth is set via inline `style`, not the `strokeWidth`
          prop: lucide sets `strokeWidth` as an SVG attribute, but a CSS
          `stroke-width` property (which `style` produces) always wins over the
          attribute -- so this stays token-driven from
          --component-icon-button-stroke-width without a React re-render on
          brand switch, the same "var(), never a literal" rule Button.tsx and
          state-overlay.mjs already follow. */}
      <Icon aria-hidden="true" size={20} style={{ strokeWidth: "var(--component-icon-button-stroke-width)" }} />
    </button>
  );
});
```

```tsx
import { Minus, Plus } from "lucide-react";

function clampBpm(value: number): number {
  return Math.min(MAX_BPM, Math.max(MIN_BPM, value));
}

export function BpmDecrementButton({ bpm, onBpmChange }: { bpm: number; onBpmChange: (bpm: number) => void }) {
  const next = clampBpm(bpm - BPM_STEP);
  return (
    <IconButton
      icon={Minus}
      variant="secondary"
      onClick={() => onBpmChange(next)}
      data-umami-event="bpm-decrement"
      data-umami-event-bpm={String(next)}
      aria-label="Decrease tempo"
    />
  );
}

export function BpmIncrementButton({ bpm, onBpmChange }: { bpm: number; onBpmChange: (bpm: number) => void }) {
  const next = clampBpm(bpm + BPM_STEP);
  return (
    <IconButton
      icon={Plus}
      variant="secondary"
      onClick={() => onBpmChange(next)}
      data-umami-event="bpm-increment"
      data-umami-event-bpm={String(next)}
      aria-label="Increase tempo"
    />
  );
}
```

Note on boundary behavior: at `bpm === MAX_BPM`, `clampBpm(bpm + BPM_STEP)` evaluates to `MAX_BPM` again, so `onBpmChange(MAX_BPM)` is called — a harmless no-op re-set, matching "clickable but silently clamps, no error" exactly, with no `disabled` logic needed.
