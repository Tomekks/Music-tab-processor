# Guide

This project has two tiers of documentation, on purpose:

- **This tier** (`docs/GUIDE.md`, `docs/ARCHITECTURE.md`, `docs/DECISIONS.md`) — plain language, for a human keeping track of their own project. What things do, why they exist, what's been decided and why.
- **`docs/specs/`** — precise, mechanical task specifications for AI coding agents: exact inputs/outputs, file locations, and a concrete "done when" checklist. No room to improvise structure.

Start with `docs/ARCHITECTURE.md` for the big picture, then `docs/DECISIONS.md` for why specific tools and approaches were chosen over the alternatives.

Everything about this project — reasoning, alternatives considered, open questions — is tracked in more depth in the planning notes kept alongside this repo; these docs are the distilled, kept-current version that lives with the code itself.
