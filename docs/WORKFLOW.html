How we work now

One page, how a task really moves today. Written 2026-10-03, brought up to date 2026-10-05 (one builder run, blind second reviewer, browser specs run by a script, launch commands in every checklist). The previous process lives in docs/old_workflow_docs/ and is not current.

Who does what

YouDecide and testApprove what a task changes, decide model switches, run your own check, say yes to any push or deploy.
ClaudePlan, brief, reviewQuestions you, writes the plan and the brief, runs one command to hand off, then reads the result and the diff.
Builder (Muse)Types the codeCheap model in its own copy of the project. Writes the tests first, then the code. Cannot push, go online or delete.
ScriptsCheck the factsMechanical checks of what actually changed. They cannot be talked into a pass by a model's own summary.

One task, start to finish

Red steps with the "you decide" tag are the only places you are needed. Dashed = optional.

Claude2. Size the taskPick Level 0, Quick or Full (see below)

Script7. WatchdogKills a dead run: nothing in 60 s, stalled for 180 s. Logs kept short (last 200 lines)
Script8. Facts check + saveOnly allowed files changed? Checks pass? Promised files exist? Then one checkpoint commit (and approved deletions)
Script9. Short summaryAbout 10 lines: pass or fail, plain reason, diff size, log path, a scorecard row with the real tokens, cost and seconds of the run
Claude10. Review and browser specs/review: Claude answers 3 questions (Level 1) or all 8 (Level 2) while a blind deepseek #high answers the same; Claude compares and checks each claim against the code. Watched UI: the builder runs scripts/run-e2e.sh (port check, run, cleanup, PASS/FAIL). Claude reads the summary and spot-checks the diff; no re-running the builder's work
You11. Your checkThe owner checklist from the brief. It opens with the launch block (free-port check, start command, stop command), then only the human checks: one action, one expected result each. Checks a browser spec already covers are marked automated
You12. ShipPush, PR or deploy only on your yes. For the app: preview with npm run stage first, then push / push and deploy / skip

Steps 5 to 9 are one command that Claude runs: scripts/delegate.sh <task file>. Nothing is copied or pasted between models; results come back through the task file and the summary.

Measuring time and tokens (automatic)

So changes to the process are judged on numbers, not on a feeling. Scripts do it; reading a report costs a few hundred tokens.

What is recorded, and when
  • A time stamp and the builder's token total at each step: /start (session start), start and end of delegate.sh, finish.sh, and /wrap (with Claude's plan usage as a note).
  • Log: .git/measure.tsv, shared by all worktrees, never shown as a change.
Where the numbers come from
  • Claude tokens: summed from the session transcripts between two marks, each message counted once (claude-usage.py). History goes back to 2026-09-07, so the old process has a baseline by day.
  • Builder tokens and cost: opencode stats --all --json, difference between marks.
  • Time: wall clock, including your waiting.
Read it
  • scripts/measure.sh report <task>: seconds, builder tokens and Claude tokens between marks.
  • scripts/measure.sh history 8: Claude tokens per day.
  • Plan or task cost = the difference between its start mark and end mark.

Three sizes of work

SizeWhenWhat you get
Level 0You can describe the change in one sentence and nothing risky is touchedNo task file, no builder. Just do it, run the check, commit.
Quick1 to 3 files of plain logic, no risk triggerThe short form (about 20 lines): one sentence, allowed files, rules, one check. new-worktree.sh --quick
FullAny risk trigger (deletes, contracts/, shell or network, schema, deploy, secrets), UI or audio, or 4+ filesThe full form with size, risk, steps and your checklist. Cold read always.

When something goes wrong

Muse is down
  1. The script retries once.
  2. Still down: it stops and names the fallback (deepseek-v4.1-flash).
  3. Claude asks you. Nothing switches silently.
The work is not acceptable
  • Files changed outside the allowed list, the checks fail, or a promised file is missing: the summary says which, in plain words, and the work is not accepted.
  • Two failed runs that are not an outage: Claude stops and reports instead of debugging the process.
Hard stops
  • A free-tier model answers: stop and tell you.
  • The builder wants to delete something not on the list: it writes a question and stops.
  • Anything unclear: it asks in the task file, it does not guess.
