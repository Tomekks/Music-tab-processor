# Patch Bay

Part of `docs/patch-bay/` — see `docs/GUIDE.md`'s map for how this fits into the rest of the docs.

**Status:** done, working, verified in-browser. A single self-contained `index.html` — open it directly, no server needed. **Also published live** at `/archytechy` on the deployed app (an unlisted, secret-link-only route — `app/public/archytechy/index.html` is a manually-synced copy; update both if either changes, `next.config.ts` carries the rewrites that make `/archytechy` and `/archytechy/` both resolve). Five tabs: development workflow, pipeline architecture, and a proposed user journey (each with a "Trace it →" guided walkthrough, click-for-detail stations, a local/hosted dashed divider, and a technology-stack panel), plus a live repo-structure file browser and a philosophy/principles tab. An ambient signal dot loops continuously along the main path in the three diagram tabs — a literal "signal path," matching the project it documents. All motion respects `prefers-reduced-motion` (disabled entirely, no exceptions).

**Fourth tab, "Files" (2026-09-11), browses the actual repo — generated from git, not the local disk.** A macOS-style column browser (`REPO_TREE`, embedded JSON built from `git ls-tree -r --name-only origin/master`, 141 files as of writing) — names and icons only, never file contents, and only what's genuinely pushed. This distinction is load-bearing: a plain filesystem scan would have leaked untracked local material (personal notes, other tool config) onto a page meant to be shared by secret link. Capped at 3 visible columns, same behavior as Finder in a narrow window.

**Fifth tab, "Philosophy & principles,"** is prose, not a diagram — the reasoning threads (recognizable-not-accurate, prove-before-building, layer separation, record-the-why, local-stays-local, machine-checks-what-it-can, you-decide) that the other tabs' facts already embody.

**Third tab, "User Journey" (2026-09-11), is deliberately not factual like the other two.** It visualizes an idea — a local, offline control-room UI for triggering pipeline runs, replacing today's five manual CLI commands — that is **not built and not confirmed feasible**. Marked unmistakably: a warn-colored "Concept — not built" badge, every node dashed rather than solid, a stat card reading "Idea · not built, feasibility not yet confirmed." One real open question is called out directly in the Transcribe station's own detail text: true mid-step pause may not be possible for a single blocking ML call (htdemucs, Basic Pitch) the way stop/abort clearly are. Status dots (done/running/pending/error) reuse the existing `--ok`/`--warn`/`--line`/`--blocked` tokens — no new shared colors introduced.

**Palette is a real theme, not a one-off.** The four core colors (background/ink/accent/border) match the `Patch bay` entry in `app/design_system/`'s theme selector exactly — select it there to preview the same palette against the app's own real components. That tool's schema has no room for this page's extra tokens (`--surface-2`, the semantic `--ok`/`--warn`/`--blocked` status colors); if the four shared colors ever change, update both files by hand — same manual-sync convention already used between `docs/backlog-board/index.html` and `docs/BACKLOG.md`.

**Controls:** accent color, light/dark/system theme, node shape (sharp/rounded/pill), text density — all persist per-browser via `localStorage`.

**Content is factual, not illustrative.** Every station's detail text names a real file, command, or date from this project — see `docs/DEVELOPMENT_PROCESS.md` and `docs/ARCHITECTURE.md`, which this page visualizes rather than replaces. One planned-but-not-built item (a local pipeline-trigger UI) is marked honestly with a dashed box, not omitted.

**Not built:** a way to regenerate this page's SVG automatically from the source docs — it's hand-authored and updated by hand when either doc changes materially, the same tradeoff `docs/backlog-board` already makes for its own content.
